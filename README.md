# ServiceMonitor — 跨平台服务状态监控工具

用 Python + Qt（PySide6）编写的服务监控工具，Windows 与 Linux 通用。
它把"启动一个服务并盯着它"这件事集中到一个窗口里：列表页看当前状态、行内直接启停，
详情页看一段时间内的 CPU / GPU / 内存曲线和每一次启动的控制台输出。

## 功能

**列表页（当前状态）**

- 启动即显示所有已添加的服务，每行给出：状态、服务名、描述、PID、CPU、GPU、当前内存、峰值内存、运行时长。
- 行内就有"启动 / 停止"按钮，不需要先进详情页。
- 状态包括：运行中、未启动、已退出、异常退出、停止中、守护等待中、启动失败、监控中断。
- 顶部工具栏：＋ 添加服务、编辑、删除、全部启动、全部停止；右上角可按名称/描述过滤。
- 双击或单击任意一行进入详情页。

**添加 / 编辑服务**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 服务名 | 是 | 列表中显示的名字 |
| 启动命令 | 是 | 交给系统 shell 执行（Windows 为 `cmd.exe /c`，Linux 为 `/bin/sh -c`），因此支持参数、管道与重定向 |
| 描述 | 否 | 备注这个服务是做什么的 |
| 工作目录 | 否 | 留空则使用监控工具自己的当前目录 |
| 是否守护 | 否 | 勾选后进程意外退出会等待若干秒自动重新拉起 |
| 重启等待 | 否 | 守护模式的重启间隔，默认 5 秒 |

监控统计的是命令派生的**整棵进程树**（例如 `cmd.exe → python.exe` 会合并计算），
停止时也会连同子进程一起结束，避免留下孤儿进程。

**详情页（历史曲线 + 控制台输出）**

- CPU / GPU / 内存三张折线图，实线为均值、虚线为峰值。
- 粒度可切换：10 秒 / 1 分钟 / 10 分钟 / 1 小时；范围可切换：10 分钟 ~ 30 天 / 全部历史。
- 图下方是"启动记录"列表：一个服务每启动一次就是一行，按时间倒序（最新的在最上面），
  显示开始时间、时长、PID、退出码 / 状态、峰值内存、输出行数。运行中的那行显示"服务运行中"，
  结束后显示退出码（例如 `3（异常退出）`、Linux 上 `-9（信号 9）`）。
- 点击某一条记录即可查看该次的完整控制台输出；stdout / stderr / 监控自身的说明行用不同颜色区分。
- 正在运行的服务会实时追加新输出。**如果你已经往上滚动，刷新不会移动你正在看的位置**，
  只会在右下角提示"↓ 回到最新（N 条新输出）"；勾掉"跟随最新输出"可以完全停止自动滚动。
- 可勾选"只看 stderr"过滤，支持复制与导出到文件。

**持久化**

监控数据与控制台输出全部写入本机 SQLite（WAL 模式），退出监控工具再启动不会丢失；
曲线是按时间桶聚合查询出来的，历史多久都能翻。上一次运行时仍在运行的会话，
下次启动会被标记为"监控中断"，不会假装它们还在跑。

**系统托盘**

关闭窗口不会退出程序，而是缩到系统托盘里继续监控——服务照常跑、输出照常入库、
守护照常拉起。

- 右键托盘图标：**打开界面** / **退出监控**。
- 左键单击或双击图标：打开界面。
- 图标右上角的绿色角标是当前运行中的服务数量，tooltip 同步显示；空闲时为纯图标。
- 第一次缩到托盘会弹一条通知说明怎么找回来。
- **同一个数据目录只跑一份监控**：已经开着的时候再启动一次（开机自启 + 手动双击最常见），
  新进程只把已有实例的界面调到前台，然后自己退出，因此托盘里不会长出第二个图标。
  用 `--home` 指向另一个数据目录时是两个独立实例，可以并存。
- **退出监控**（或菜单里的 文件 → 退出）才真正结束进程，并按"退出时停止服务"的设置收尾。
- 不想要这个行为的话，在 文件 → 设置… 的"点击关闭按钮时"里选**完全退出**，
  关窗即退出。**桌面没有可用托盘时（部分 Linux 环境）会自动退回"关窗即退出"**，
  避免应用变成再也找不到的隐形进程。

## 安装

需要 Python 3.9+（开发验证使用 3.13）。依赖只有 PySide6 与 psutil，都是官方 wheel。

**Windows**

双击仓库根目录的 `start-monitor.bat` 即可：脚本只调用 `run.ps1 -Hidden`，和手动执行
`.\run.ps1` 是同一条路径，虚拟环境与依赖由 `run.ps1` / `setup.ps1` 准备（首次运行需要几分钟，
那一次会看到安装日志滚过）。之后双击只闪一下启动窗口，桌面上**不会留一个常驻的控制台**：
监控挂在一个隐藏的控制台上跑，界面照常出现。

要看实时输出或传参数，用 PowerShell 前台启动（`--demo`、`--home` 只走这条路径）：

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1   # 创建 .venv 并安装依赖
.\run.ps1                                            # 启动
.\run.ps1 --demo                                     # 顺便插入两个示例服务
```

**Linux / macOS**

```bash
bash setup.sh
./run.sh
./run.sh --demo
```

Linux 上 Qt 需要系统图形库（`libEGL`、`libxcb`、`libxkbcommon` 等）。
若启动时报缺库，请安装发行版的 Qt6 运行库（Debian/Ubuntu 通常是
`sudo apt install libxcb-cursor0 libegl1 libxkbcommon0`）。

手动安装等价于：

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt    # Windows 为 .venv\Scripts\python.exe
.venv/bin/python monitor.py                            # 或 --demo
```

## 数据存放位置

| 平台 | 目录 |
| --- | --- |
| Windows | `%APPDATA%\ServiceMonitor` |
| Linux | `$XDG_DATA_HOME/ServiceMonitor`，未设置时 `~/.local/share/ServiceMonitor` |
| 任意平台 | `--home /path` 或环境变量 `SERVICEMONITOR_HOME` 覆盖 |

目录内是 `monitor.db`（服务、会话、采样、输出）与 `settings.json`（采样间隔等设置）。
设置对话框底部会显示当前数据目录，"文件 → 打开数据目录"可直接跳转。

## GPU 监控

通过 `nvidia-smi` 采集：整机 GPU 利用率，以及按 PID 匹配的显存占用。
没有 NVIDIA 驱动 / 找不到 `nvidia-smi` 时自动降级，GPU 列显示 `—`，
详情页会写明原因（"该服务没有 GPU 占用"或"GPU 采集已在设置中关闭"），不会报错。
非 NVIDIA 显卡（AMD/Intel）目前不提供利用率数据。

## 设置项

文件 → 设置…（`Ctrl+,`）：

| 设置 | 说明 |
| --- | --- |
| 采样间隔 | 默认 2 秒，最小 0.5 秒 |
| GPU 采集 / 刷新间隔 | 关闭后 GPU 列显示 `—`，不再调用 `nvidia-smi` |
| 界面字体 | 默认"（跟随系统默认）"，选中某字体族后所有界面立即换字体 |
| 界面字号 | 7–24 磅，默认 10 磅；输出面板跟着一起放大 |
| 点击关闭按钮时 | **缩到系统托盘**（默认）/ **完全退出**；检测不到托盘时自动退回完全退出 |
| 开机后自动启动 | Windows 写当前用户的 `HKCU\…\CurrentVersion\Run`，Linux 写 `$XDG_CONFIG_HOME/autostart\servicemonitor.desktop`；只影响当前用户，取消勾选即删除 |
| 退出时停止服务 | 默认停止由本工具启动的服务 |
| 数据保留 / 曲线点数 / 守护重启等待 | 历史清理天数（0 = 永久）、单条曲线最大点数、意外死亡后的拉起延迟 |

设置写入数据目录下的 `settings.json`，重启后保持。开机自启不落在 `settings.json` 里，
它直接以系统登录项为准——对话框打开时会读取当前真实状态。

菜单：文件（添加服务 / 设置 / 打开数据目录 / 退出）、控制（启动全部 / 停止全部 /
按保留策略清理历史数据）、视图（返回服务列表 `Esc` / 立即刷新 `F5`）、帮助（关于）。

## 已知边界

- 首次运行由 `run.ps1` 调 `setup.ps1` 创建 `.venv` 并联网安装依赖，需要几分钟；虚拟环境固定
  建在脚本所在目录，换目录存放请连同 `.venv` 一起移动。
- Windows 上调用 `nvidia-smi`、`taskkill` 这类内部工具时会带 `CREATE_NO_WINDOW`：以前从
  无控制台的 `pythonw`（开机自启就是这条路径）启动时，每次调用都新开一个黑框，GPU 每 5 秒
  两次，看上去就是"不定时闪一个 cmd 窗口"。被监控的服务本身不加这个标志——它要靠共享
  控制台收 `CTRL_BREAK` 才能优雅停止；实测也不会闪窗，因为它的 stdout/stderr 是管道、
  stdin 是空设备，三个句柄都不指向控制台时 conhost 不会创建窗口。
- 单实例锁的名字由数据目录算出来（Windows 是命名管道，Linux/macOS 是本地 socket 文件），
  异常退出后残留的 socket 文件会在下次启动时清掉并重新监听。
- 交给服务的 PATH 会剔掉 `C:\Program Files\WindowsApps\<包名>` 这类应用包目录：监控跑在
  商店版 Python 上时，解释器把自己的包目录塞到 PATH 第 0 位，而那个目录包外的进程无权执行，
  服务里一句 `python` 只会打印"拒绝访问。"（`python --version` 返回 1），用户双击同一个 bat
  却正常。剔掉之后服务解析到的就是用户平时用的 app execution alias 目录。
- Windows 的优雅停止用 `CTRL_BREAK`，它只能发给**和自己共用控制台**的进程：所以用
  `start-monitor.bat` / `run.ps1` 启动时服务能优雅退出；开机自启（`pythonw`，没有控制台）
  时发不出去，会等满"优雅停止等待"（默认 5 秒）再强杀整棵进程树，行为与以前一致。
- 界面字号通过样式表生效，Qt 会在重设样式表时重新解析字体族，因此改字体的顺序是
  "先应用字体、再重设样式"；输出面板始终锁定等宽字体，不会被界面字体带跑。
- CPU 利用率按"占用了一个核 = 100%"计算，与任务管理器/`top` 的单核口径一致。
- 采样间隔默认 2 秒，短于一个采样周期的闪退可能只留下退出记录而没有曲线点。
- 输出面板最多渲染 8000 行（数据库里始终是全量），超出后会停止追加并提示手动跳到最新，
  以免界面被巨型日志拖住。
- 控制台输出编码按 UTF-8 → 系统本地编码 → GB18030 逐级尝试，因此 Windows 上 GBK 程序
  与 Linux 上 UTF-8 程序的中文都能正确显示。
- Linux 的托盘需要面板提供 SNI/StatusNotifier 支持：KDE、XFCE、Cinnamon 直接可用，
  GNOME 需安装 AppIndicator 扩展。检测不到托盘时程序会自动退回"关窗即退出"。
